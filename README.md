# Рацион на двоих

Личное приложение: меню на неделю, бюджет и общий список покупок. GitHub Pages + Supabase, без собственного сервера. План развития — [PLAN.md](PLAN.md).

## Локальная проверка

Нужен Node.js 20 или новее. Устанавливать библиотеки не требуется.

```sh
npm test
npm start
```

Открыть http://127.0.0.1:4177. Пока `public/config.js` пустой, данные сохраняются только в браузере этого устройства. Это деморежим, он не синхронизируется между телефонами. После подключения облака демоданные автоматически не переносятся.

## Публикация GitHub Pages

1. Загрузить содержимое этой папки в корень репозитория `D3SKII/diet` в ветку `main`.
2. В GitHub открыть Settings → Pages → Source → GitHub Actions.
3. Запустить workflow `Publish app` во вкладке Actions либо отправить новый commit.
4. После успешной публикации ожидаемая ссылка: https://d3skii.github.io/diet/ . До успешного deploy ссылка не подтверждена.

GitHub Pages доступен для публичных репозиториев на GitHub Free. Личные данные не должны лежать в репозитории: они хранятся в Supabase. Публичный код приложения не даёт доступа к рациону, если SQL-политики настроены правильно.

## Подключение общего аккаунта

1. Создать проект на https://supabase.com/ . Сохранить пароль базы у себя.
2. В SQL Editor выполнить `supabase/schema.sql` один раз.
3. В Authentication → Users создать одного пользователя с вашей общей почтой и паролем (через Add user / Create user, подтвердить почту). Оба телефона используют этого пользователя. Отдельного аккаунта для девушки пока не нужно.
4. В настройках Auth отключить регистрацию новых пользователей, если приложением пользуетесь только вы. Вход существующего пользователя продолжит работать.
5. В Connect / API settings получить Project URL и **publishable** ключ (либо legacy `anon` ключ).
6. Записать эти два публичных значения в `public/config.js` и отправить изменения в GitHub:

```js
export const config = {
  supabaseUrl: 'https://ВАШ-ПРОЕКТ.supabase.co',
  supabaseKey: 'ВАШ-ПУБЛИЧНЫЙ-КЛЮЧ'
};
```

**Нельзя публиковать пароль, secret или service_role ключ.** Публичный ключ предназначен для клиента. Доступ к данным защищён авторизацией и RLS. Без выполнения SQL облако работать не будет.

7. Открыть опубликованное приложение на обоих телефонах и войти с общей почтой/паролем. Изменить настройку на одном и проверить её на другом примерно через 10 секунд.

Проверка изоляции: пользователь B не должен видеть меню пользователя A. Проверка конфликта: открыть настройки на обоих телефонах, сохранить на первом, затем на втором — вторая запись должна быть отклонена с предложением обновить страницу.

## Установка на телефон

После публикации по HTTPS: Android — меню браузера → Установить приложение / Добавить на главный экран. iPhone — меню Поделиться → На экран «Домой». Точное название зависит от браузера. Без сети доступен кеш интерфейса, но облачные данные и их изменение требуют соединения.

## Проверка и ограничения

```sh
npm test
npm run build
```

Тесты проверяют упаковки, остатки, цены, ограничения подбора и превышение бюджета. Облачные интеграционные тесты требуют настроенного проекта Supabase. Сгенерированный каталог — стартовый набор с демонстрационными ценами. Это планировщик покупок, полноценная оптимизация питания и расчёт КБЖУ пока не реализованы.

Документация платформ: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [Supabase Auth](https://supabase.com/docs/guides/auth/passwords), [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [установка PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).
